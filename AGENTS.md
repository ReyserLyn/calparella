# CalParella — Agent Guide

## Stack

**Runtime:** Astro 6 + Cloudflare Workers (NOT Pages) + workerd
**Auth:** Better Auth (`better-auth/minimal`) + Drizzle adapter
**DB:** Cloudflare D1 (binding `DB`) + Drizzle ORM + `drizzle-kit`
**Storage:** R2 (binding `CALPARELLA`, bucket `calparella`), KV (binding `SESSION`)
**Styles:** Tailwind v4 (`@theme inline`, OKLCH, dark/light)
**UI primitives:** `@data-slot/*` (dialog, dropdown-menu, hover-card, toggle, tooltip) — NOT React-based
**Icons:** HugeIcons (`@hugeicons/core-free-icons`)
**Package manager:** `bun`
**Node:** >= 22.12.0
**No React** — vanilla Astro + TypeScript

## Key commands

```bash
bun run dev        # wrangler types && astro dev
bun run build      # wrangler types && astro check && astro build
bun run deploy     # wrangler types && astro build && wrangler deploy
bun run validate   # lint && check && format — run before committing
bun run db:generate     # drizzle-kit generate
bun run db:migrate:local  # apply migrations to local D1
bun run db:migrate:prod   # apply migrations to production D1
bun run db:push          # drizzle-kit push (needs .env credentials)
```

All commands that touch Cloudflare run `wrangler types` first to regenerate `worker-configuration.d.ts`.

## Critical gotchas

### `worker-configuration.d.ts` is gitignored

Must be generated before TypeScript can resolve Cloudflare bindings. Generated by `wrangler types` (already in all `bun run` scripts). After `bun install` with a new lockfile, run `bun x wrangler types` once.

### R2 binding is `CALPARELLA`, not `calparella`

In code: `env.CALPARELLA` (from `cloudflare:workers`). The bucket name is `calparella` — the binding name is uppercase.

### D1 binding is `DB`

In code: `env.DB`. The database name is `calparella`, the binding is `DB`.

### No `*.workers.dev` URL

`workers_dev: false` in wrangler.jsonc. Deploy only to custom domain `calparella.site`. No dev subdomain.

### Vite v7 override

`package.json` overrides Vite to v7 (`"overrides": { "vite": "^7" }`). Astro 6 requires Vite 7. Do not install Vite 6.

### `verbatimModuleSyntax: true`

All type-only imports **must** use `import type { ... }` or `import { type ... }`. Runtime-only imports without the `type` keyword will fail the build.

### Password hashing: `node:crypto.scryptSync` (not JS)

Pure-JS scrypt (`@noble/hashes`) exceeds Cloudflare Workers CPU time limit. `scryptSync` is native (libuv thread pool), compatible via `nodejs_compat`. Requires `nodejs_compat` in `wrangler.jsonc` (already set). Do NOT replace with bcryptjs or noble-hashes.

## Astro v6 + Cloudflare adapter quirks

- **NO** `Astro.locals.runtime` — removed in v13 adapter.
- Use `import { env } from 'cloudflare:workers'` for bindings (D1, KV, R2).
- Use `Astro.locals.cfContext` for `ExecutionContext` (`waitUntil`).
- Use `Astro.request.cf` for geolocation data.
- Dev server runs through **workerd** (not Node.js) → no request logs in terminal.
- Vite optimizer cache (`node_modules/.vite`) may corrupt after lockfile changes; delete and restart.

## Auth architecture

- `src/lib/auth.ts` exports both `createAuth(env?, ctx?, baseURL?)` (runtime factory) and `export const auth = createAuth()` (CLI schema generation for `bun x @better-auth/cli generate`).
- **One auth instance per request**: middleware (`src/middleware.ts`) creates it, stores in `locals.auth`, API route reuses it. Avoids D1 WAL lock contention.
- KV `SESSION` namespace used for secondary storage + rate limiting. KV TTL clamped to 60s minimum.
- `cookieCache` enabled (15 min), `updateAge` (15 min), `backgroundTasks` via `ctx.waitUntil`.
- `src/lib/auth-client.ts` uses vanilla `createAuthClient()` (no React).
- Custom password hashing: `src/lib/password.ts` (see gotcha above).

## DB + migrations

- **Schema:** `src/db/schema.ts` — Better Auth tables (users, sessions, accounts, verifications) + app tables (calendars, calendar_members, calendar_photos, invitations). All plural, camelCase columns.
- **Migrations dir:** `./src/db/migrations` (must match both `drizzle.config.ts` and `wrangler.jsonc`).
- `drizzle-kit push` uses `d1-http` driver → needs Cloudflare API credentials in `.env`.
- `wrangler d1 migrations apply` is the prod-safe path.
- `src/db/index.ts` exports the Drizzle client factory (one instance per `env.DB`).

## Secrets & env

| File                    | Purpose                                        | Git       |
| ----------------------- | ---------------------------------------------- | --------- |
| `.env`                  | drizzle-kit credentials (Cloudflare API token) | ignored   |
| `.dev.vars`             | local dev secrets (`BETTER_AUTH_SECRET`)       | ignored   |
| `wrangler.jsonc` `vars` | non-sensitive vars (`BETTER_AUTH_URL`)         | committed |
| `wrangler secret put`   | production secrets (`BETTER_AUTH_SECRET`)      | CLI only  |

**Gotcha:** `BETTER_AUTH_SECRET` is a wrangler secret, NOT in wrangler.jsonc vars. Do NOT reference `env.BETTER_AUTH_SECRET` in code (it won't be in generated types in CI). Better Auth reads it from `process.env` automatically.

## Conventions

- **Formatting**: Prettier — no semicolons, single quotes, trailing commas, 100 width. `public/` is prettier-ignored.
- **Tailwind v4**: Uses `@theme inline` + `@layer utilities` for custom fonts. OKLCH color space.
- **Path alias**: `@/` → `src/` in `tsconfig.json`.
- **Fonts**: Local `.woff2` in `src/assets/fonts/`, configured via Astro `fonts` config (DynaPuff, CherryBombOne, EmilysCandy — no Google Fonts).
- **Git**: Two branches — `production` + `dev`.
- **`components.json`**: Bejamas Juno style, HugeIcons. **WARNING**: has stale `"css": "src/styles/global.css"` — actual path is `src/styles/globals.css`.
- **No CI**: `.github/workflows/` does not exist yet. All validation is local.
